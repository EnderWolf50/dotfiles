# Windows shell

The Bash tool runs Git Bash on Windows, beside Node and pwsh. Each item is a place where a value crossing between them changes on the way.

- **Command length (about 7.5 KB)**: Git for Windows (MSYS, Git 2.55.0.windows.5) silently truncates a command-line argument that contains spaces above about 8186 characters. The Bash tool passes the whole command as one `bash -c` argument, with what Claude Code prepends from `~/.claude/session-env/<session>/`, so a command over about 7.5 KB is cut off and exits 0 with no output (the same cut shows as `unexpected EOF` when it lands inside a quote). Write a long script to a file with the Write tool and run it by path. Do not set `MSYS=noglob`: it avoids the cut but breaks double quotes. When every Bash call returns empty, check the size of `~/.claude/session-env/<session>/sessionstart-hook-*.sh`: the impeccable SessionStart hook appends a line to it on every resume, and a long-lived session can fill the budget by itself.
- **`gh pr checks` exit codes**: exit 8 means checks are still pending (`gh pr checks --help`, "Additional exit codes"), not an error; exit 1 is any failure, such as a failed check. Do not retry or abort on 8: wait with `gh pr checks <n> --watch` (it returns when the checks finish) and read the exit code after it.
- **`gh --jq` quoting**: the jq program goes in single quotes in both shells, with its inner double quotes as they are: `gh pr list --json number,title --jq '.[0] | "\(.number) \(.title)"'` works in Git Bash and in pwsh 7 (`$PSNativeCommandArgumentPassing` is `Windows`). Escaping the quotes as `\"` for pwsh breaks the program with a jq parse error. A jq type error is not a quoting error: `.number + " "` fails (number plus string), so build text with string interpolation, `[.number, .title] | join(" ")` or `@tsv`. For a long jq program, put it in a file and pass `--jq "$(cat prog.jq)"` (Git Bash) or `--jq (Get-Content -Raw prog.jq)` (pwsh), or use `--template`.
- **Path arguments**: Git Bash rewrites `/Foo`-style arguments into Windows paths; prefix `MSYS_NO_PATHCONV=1` (adb, `git show rev:path`, URL paths in env vars).
- **Two `/tmp` folders**: Node and Python resolve `/tmp` to `D:\tmp` (the current drive), Git Bash to its own temp folder, so `cmd > /tmp/x.txt; node -e 'readFileSync("/tmp/x.txt")'` reads a missing or stale file. Hand another program a Windows path: write the file under the repo or the scratchpad and pass that absolute path, or convert a Git Bash path with `cygpath -m` (`f=$(cygpath -m "$(mktemp)")`) before passing it on.
- **Line ends**: scoop `jq` and pwsh output end lines in `\r`; pipe through `tr -d '\r'` before comparing.
- **Console encoding**: a script without the profile (chezmoi scripts, `pwsh -NoProfile`) decodes a native command's output with the console code page, which garbles UTF-8 (CJK, `—`): set `[Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)` before capturing it.
- **Python console output**: `PYTHONUTF8=1` is set at User level, but `python -I` and `-E` ignore every `PYTHON*` variable and fall back to the console code page, which raises `UnicodeEncodeError` on CJK text. Add `-X utf8` to such a run, or call `sys.stdout.reconfigure(encoding="utf-8")` first.
- **pwsh arguments**: `pwsh -Command '<script>' <args>` drops the trailing args (no `$args`): pass values through env vars, or write the script to a file and use `-File`.
- **Doubled backslash**: the Bash tool turns every `\\` in a command into `\` before Git Bash runs it, inside single quotes and a quoted heredoc too: `printf '%s' 'S\\Q'` prints `S\Q`. A single `\` passes, and a file keeps every `\`: write the text with the Write tool (not `printf >` or a heredoc, which go through the same halving) and run or pass it by path. The guards plugin denies a Bash command containing `\\` on Windows.
- **Inline scripts**: a program fed to an interpreter through `-e`/`-c`, a pipe or a heredoc (`node -e`, `node - <<'EOF'`, `python -c`, `pwsh -c`, `sed`) crosses three or four quoting layers (the Bash tool, Git Bash, the interpreter, a JS template literal) and loses characters on the way: inside a template literal `[\s\S]` arrives as `[sS]` and `\w` as `w`, `$env:A:B` fails to parse, a `\\n` lands as a real newline (Doubled backslash). Write the program to a file in the scratchpad with the Write tool, then run it by path (`node <file>`, `python <file>`, `pwsh -NoProfile -File <file>`). A one-line program with no quotes, `$`, backticks or backslashes can stay inline.
- **Folder sizes**: Git Bash `du -sh` over a large NTFS tree runs for minutes (two runs over a 300 GB repo hit 240 s and 300 s timeouts with no output, 2026-10-29). Sum it in pwsh, which finished the same trees in tens of seconds: `(Get-ChildItem -LiteralPath <dir> -Recurse -File -Force -ErrorAction SilentlyContinue | Measure-Object Length -Sum).Sum`, one call per child to rank them.
- **Deleting the working folder**: Windows refuses to remove a folder a process sits in, so `rm -rf <dir>` fails with `Device or resource busy` while the Bash tool's cwd is inside it (the session cwd follows an earlier `cd`). `cd` to its parent in the same command first: `cd <parent> && rm -rf <dir>`.
